# 目标：按原作重设计怪兽招式动画 + 哉佩利敖光线前摇

## Goal

把现在「所有 MMD 怪兽共用一套 `aimLimb` 姿势」的做法换成**按角色设计的招式动画**，并让**哉佩利敖光线**具备独立的、比梅特里姆光线更强也更长前摇的两阶段判定。全部验证都要能在**不开摄像头**的前提下核验，最后发布一版到 https://adoin.github.io/ultraman-play/ 供实机查看。

## 目标结果

1. 9 只 MMD 怪兽（`baltan`、`mefilas`、`chaos-seven`、`chaos-taro`、`chaos-ultraman`、`zetton`、`gomora-mecha`、`galactron`、`gatanothor`）各自拥有贴合原作设定的攻击动作；同一种招式种类在不同怪兽身上不再复用同一姿势。红王与加恩Q 已有独立的非 MMD 动作路径，保持现状。
2. 每只怪兽的原作招式名、动作要点与二级出处整理成文档，并让游戏内招式名与文档一致。
3. 哉佩利敖光线：手势判定变成**两阶段前摇**（先聚气，再摆 L 形），只有走完前摇才会释放；第一人称手臂动画有**明显区别于梅特里姆光线**的前摇阶段。
4. 新增可离线运行的姿势/判定验证能力（断言 + 截图），不依赖摄像头。
5. 全量既有检查保持通过，构建成功，站点与源码两个仓库均已发布。

## Acceptance criteria（全部可客观核验）

1. **新增 `npm run test:poses`（脚本 exit 0）**，覆盖 9 只怪兽 ×（其 `WAVES[].attacks` 全部种类 + `melee`）：
   - 每个（怪兽, 招式）组合在蓄力中段与出手中段抓取关键骨（双手、头、髋、双脚）世界坐标生成签名，与该怪兽**待机签名**差异 ≥ 脚本内声明阈值；
   - 对 `bolt` / `sweep` / `slam` / `melee` 四类，**任意两只怪兽之间的签名差异 ≥ 阈值**（证明不再共用同一姿势）；`charge` 允许共有前冲特征，但仍须与待机不同；
   - 为每个组合输出带文字标注的截图到 `artifacts/poses/`，并打印覆盖清单（9 只 × 各类别）。
2. **`npm run test:poses` 内含原作特征断言并通过**：
   - `chaos-ultraman` 的 `bolt` 出手帧双手在胸前中线两侧（各 |x| ≤ 1.5 单位）且双臂交叉呈「＋」（手到对侧前臂距离 ≤ 阈值）；
   - `chaos-taro` 的 `bolt` 出手帧双臂呈水平 T（双手高度差 ≤ 0.6 单位、水平展开 ≥ 3 单位）；
   - `chaos-seven` 的 `bolt` 蓄力帧右手到头部的距离 ≤ 2.5 单位（头镖/额头动作），出手帧手臂向前；
   - `zetton` 的 `bolt` 发射点位于面部/颈部高度且蓄力帧双手上抬 ≥ 阈值（一兆度火球从脸侧发出）；
   - `gomora-mecha` 的 `sweep` 蓄力帧头部角（`頭`）参与动作且上身抬起；`gatanothor` 的 `slam` 出手帧双手同时下压（双手高度差 ≤ 阈值、位移 ≥ 阈值）。
   - 阈值由实现选定并写入脚本常量；核验方式为「有对应断言且通过」。
3. **`docs/monster-moves.md` 存在并与代码一致**：列出 9 只怪兽 × 每个招式的原作招式名（日/英/中）、动作要点、二级来源 URL；新增测试断言 `src/combat.js` 的 `MONSTER_ATTACK_NAMES` 与文档中的正式名集合完全一致（无多余、无缺失）。
4. **哉佩利敖光线前摇**：
   - `src/action-timing.js` 导出 `ZEPELLION_TIMING`，含 ≥3 个阶段（聚气/成形/发射），其 ready 段时长 ≥ 梅特里姆光线 ready 的 **1.5 倍**，impact 至少比 `BEAM_TIMING.impact` 晚 **0.2s**；新增单元测试断言这些关系；
   - `src/gestures.js` 输出 `out.zepellionStage` ∈ {0,1,2}（0=无、1=已聚气、2=L 形成形），并新增 ≥3 条 fixture 测试：**只有 L 形不触发**、**聚气→L 形触发且仅一次**、**聚气后未保持足够时长不触发**；同时断言 zepellion 定姿时长 ≥ beam 定姿时长的 1.5 倍（easy 与 normal 各一条）；
   - 新增 `npm run test:poses`（或并列脚本）采样第一人称手骨在「聚气阶段」的位置，断言与梅特里姆光线同时刻手部位置差异 ≥ 阈值，并输出该阶段截图，证明前摇是独立动作而非复用；
   - 聚气阶段 HUD 文本包含阶段提示（可用页面文本断言）。
5. **既有检查全绿**：`npm test`、`npm run test:models`、`npm run test:enemies`、`npm run test:feedback` 全部通过；`npm run build` 成功。
6. **线上复验**（对 https://adoin.github.io/ultraman-play/ 运行的脚本通过）：11 波且末波为 `gatanothor`；`SKILLS` 数值保持 `zepellion 82/9s`、`beam 46/6.5s`、`disc 31/2s`、`palm 14`；把波次设到杰顿并 `beginAttack('bolt')` 时威胁提示文本包含其原作招式名（如「一兆度火球」）；无 pageerror、无 4xx。
7. **发布完成**：站点仓库 `adoin/ultraman-play` 与源码仓库 `adoin/IAmUltraman` 均已提交推送，工作区干净；README 与 `art/README.md` 已补充招式表、新脚本与验证方式说明，并给出截图目录。

## Boundaries

- 不改数值平衡：11 波、血量、技能冷却/伤害、键位、护盾与闪避规则保持不变；唯二允许的变化是哉佩利敖的定姿时长与其前摇判定。
- 不新增怪兽/波次；不改动既有 GLB 的几何与骨骼（若某姿势必须重转模型，需在文档中单独记录原因与产物）。
- 不引入受版权保护的视频/音频/图片素材；原作招式资料只以文字表 + 二级来源链接形式引用。
- 验证不得依赖摄像头，也不得让摄像头模式功能回退。
- 不删除既有测试；修改已有断言时必须保持原有覆盖语义。
- 不动与本次无关的文件；两个仓库都必须保持 `npm test` + `npm run build` 通过（CI 契约不变）。
